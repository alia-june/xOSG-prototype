# MAGE Core — scoped architectural record

**Source basis:** operator-supplied historical `MageCore.zip`, inspected without executing the contained tools.  
**Version declared by source:** `0.1.7-prealpha`  
**Disposition:** defunct, not admitted, not integrated, not security-attested.  
**Identity policy:** subject-specific local research records omitted; project name retained for traceability.

## 1. Core function

MAGE expands to **Meta Amorphous Guarded Environment Gestalt**. Its archived proposal describes a durable, project-portable envelope for contracts, source references, capability boundaries, evidence, and recovery. A project may attach through a small declared descriptor that pins core identity and version.

This is an architecture description; no runnable implementation is included in this public projection.

## 2. Separation of concerns

| Concern | Proposed obligation |
| --- | --- |
| Purpose | Preserve the governing human/project goal and authorized scope |
| Evidence | Keep declarations, observations, inference, source provenance, and conflicts distinguishable |
| Reasoning | Treat model suggestions as advisory rather than as adopted instructions |
| Capability | Describe what tools can do separately from what they are allowed to do |
| Enforcement | Require independent deterministic checks before consequential operations |
| Audit/recovery | Preserve enough evidence and independent recovery paths to inspect failures |

The archived contract distinguishes availability from authority and reporting from successful execution. It expressly does **not** claim autonomous sovereign agency, identity authentication, hardware isolation, or a general actuator.

## 3. Proposed attachment discipline

A host project is expected to retain project-local intent, policy, admitted capabilities, and evidence. The historical design prefers a thin attachment descriptor over wholesale import of the core. A version mismatch is a stop condition, not implicit permission to upgrade.

## 4. Mining stages as design history

The historical staged workflow is recorded only as an abstract method:

1. Validate source/output separation and read-only policy before access.
2. Inventory explicitly authorized objects without extracting their contents.
3. Classify source objects before proposing content extraction.
4. Extract only specifically admitted classes within bounds.
5. Form provenance-labeled candidates and inspect contradictions.
6. Compare variants and propose adoption only after review.

This record does not identify, reproduce, or expose any inventoried personal data, local paths, mined documents, or private evidence. Staged procedures are not proof that a specific implementation enforced them.
